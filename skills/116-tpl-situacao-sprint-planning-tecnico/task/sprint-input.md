# Bi-weekly sprint requirements input (product description, fairly rough)

5-person development team, bi-weekly sprints. Below are the three major requirements for the next sprint, plus historical technical debt.

## Requirement 1: Mobile login/registration overhaul

Current state: The app only has account-and-password login; registration requires filling out a bunch of forms, and new-user drop-off is significant.
Goal: Switch to phone number + SMS verification code login, support WeChat one-tap login; keep the existing account-and-password login as a fallback; change the forgot-password flow to phone number reset.
Scope: iOS / Android both platforms + backend login API + SMS service integration.
Notes: The UI design mockups are not finalized; expected to be delivered around the middle of the sprint. Frontend pages can first be scaffolded following the existing design spec.

## Requirement 2: Order export performance optimization

Current state: Admin backend order export times out when there are more than 10,000 orders (synchronous generation, can't get a result within 10 minutes).
Goal: Switch export to an async task: generated by a backend queue → after completion, send an in-site message + download link; support exporting 100,000 orders; large files (>100MB) switch to chunked download.
Scope: Backend export service + task queue + admin backend frontend interaction changes.

## Requirement 3: Admin backend permission system upgrade

Current state: Permissions are hardcoded strings (e.g., `if (user.role === 'admin')`); new employees need code changes to get permissions enabled, and the audit also flagged permissions as too broad.
Goal: RBAC model: role → permission matrix; visual configuration of role permissions in the backend; operation audit logs (who changed what permission and when).
Scope: Permission model design + admin backend + replacement of existing hardcoded permission points + audit log table.

## Historical technical debt (left over from the last sprint)

- Deprecated old API: `/api/v1/orders` has been replaced by the new API, but some old-version apps still call it. Impact: old versions are no longer maintained; the API poses a security risk, consumes deployment resources, and is often misused in new development. Recommended to be taken offline within this sprint.
